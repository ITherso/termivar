# Contributors

Termivar is preparing for its first merged contribution from outside the original maintainer account. Contributor counts are based on merged Git history; bots, issue authors, and unmerged pull requests are not presented as contributors.

## Start here

1. Pick a scoped [`good first issue`](https://github.com/ITherso/termivar/labels/good%20first%20issue).
2. Comment on the issue before implementation so two people do not duplicate work.
3. Follow the [contribution guide](CONTRIBUTING.md) and open a focused pull request.
4. Include the exact validation commands and results in the pull request description.

Starter issues avoid architectural rewrites, unbounded security research, and undocumented public API changes. Maintainers should provide a problem statement, files in scope, acceptance criteria, and one primary validation command.

## Recognition

- Merged code and documentation contributors appear in Git history and release notes.
- Significant sustained contributors may be invited to help triage or review in their demonstrated area.
- Valid coordinated vulnerability reports are credited under the [Security Policy](https://github.com/ITherso/termivar/blob/main/SECURITY.md), subject to the reporter's preference.
- Authorship or credit is never sold and is not granted for generated noise, spam, or unverifiable claims.

The project will add a named contributor list after the first external pull request is merged. Until then, this page intentionally does not fabricate community participation.
